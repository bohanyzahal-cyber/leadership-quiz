**המבחן בחומר פתוח, ומותר להיכנס עם 5 דפים — כלומר 10 עמודים.** החוברת כאן היא בדיוק 10 עמודים, להדפסה דו-צדדית.

**▶ [בוחן התרגול](https://bohanyzahal-cyber.github.io/leadership-quiz/)** — 356 שאלות בהיקף המבחן, מצב תרגול וסימולציית מבחן. אפשר להדפיס מתוכו את השאלות, עם תשובות או בלעדיהן.

**▶ [חוברת החומר הפתוח](https://bohanyzahal-cyber.github.io/leadership-quiz/%D7%97%D7%95%D7%9E%D7%A8-%D7%A4%D7%AA%D7%95%D7%97.html)** — **10 עמודי A4 = 5 דפים בדיוק**, עם לשוניות ניווט צבעוניות ומפתח א״ב. בנויה לאיתור מהיר תחת לחץ זמן.

**▶ [אותה חוברת בוורד](https://github.com/bohanyzahal-cyber/leadership-quiz/raw/main/%D7%97%D7%95%D7%9E%D7%A8%20%D7%A4%D7%AA%D7%95%D7%97%20-%20%D7%9E%D7%A0%D7%94%D7%99%D7%92%D7%95%D7%AA%20%D7%91%D7%A0%D7%99%D7%94%D7%95%D7%9C.docx)** — למי שרוצה לערוך את הניסוח, להוסיף או להוריד. שתי עמודות ושוליים צרים, כדי שיישאר בסביבות 9-10 עמודים גם אחרי עריכה. **זה גם מסלול העדכון:** עורכים את הוורד, מריצים `exam/from_docx.py`, והחוברת באתר מתעדכנת.

## שני הסיכומים — ומה זה אומר על ההיקף

המאגר נבנה בתחילה מסיכום קורס מלא. לאחר מכן התקבל **סיכום מקוצר למבחן**, שהוא צר יותר: נשמטו ממנו נושאים שלמים, ונוספו נושאים שלא היו בקודם.

**נוסף בסיכום המקוצר** (ונכתבו עליו שאלות חדשות): מודל **טאקמן** לשלבי התפתחות צוות · ההבחנה בין **קבוצה לצוות** · **מודל חמשת הגורמים (Big Five)** ודגשי המרצה עליו · 14 עקרונות **פיול** · נוסחת **MPS** · מודל **SWOT** · **מנהיגות עסקתית** כשם נרדף למתגמלת · **טפלון** · המסגרת **מוטיבציה 1.0/2.0/3.0** · ניסויי **הארלו** על קופי רזוס.

**נשמט מהסיכום המקוצר:** רדין · וורום-ייטון · תיאוריית המשאבים הקוגניטיביים · נתיב-מטרה (האוס) · צדק ארגוני וארבעת סוגיו · שלוש צורות ההוגנות · פרידמן · אפקט סוייר · ניסויי דיסי.

**ובנוסף — נושא המוטיבציה ירד מהמבחן.** זהו הנושא הגדול ביותר שיצא: 92 שאלות (מסלאו, אלדרפר, הרצברג, מקללנד, הקמן ואולדהם, לוק, אדמס, ורום, פינק והארלו). הוא הוסר גם מהחוברת.

### מה נעשה עם 136 השאלות שמחוץ להיקף

הן **לא נמחקו** — הן נכונות עובדתית — אלא סומנו במקור **`מחוץ להיקף`**, וההפרדה מהן מוחלטת:

- **מחוץ להיקף ברירת המחדל.** ברירת המחדל היא **היקף המבחן** — 356 שאלות.
- **תווית אדומה** ⚠ מחוץ להיקף המבחן ליד כל שאלה כזו, גם בתרגול וגם בהדפסה.
- **אזהרה במסך ההגדרות** ברגע שהבחירה כוללת אותן.
- **אינן בחוברת החומר הפתוח.**

בורר ההיקף צומצם לשלושה כפתורים בלבד — **שאלות מבחן · היקף המבחן · הכל**. קודם הופיעו לצידם גם כפתורים לכל מקור בנפרד; הם היו כפילות ורק הוסיפו רעש למסך.

### תיקוני עובדה שהסיכום החדש חשף

- **חוללות עצמית ≠ אפקט פיגמליון.** הסיכום הישן איחד ביניהם. החדש מפריד: חוללות עצמית (Self-Efficacy, **בנדורה**) היא אמונת האדם ביכולתו; פיגמליון הוא השפעת ציפיות של **אחרים**.
- **קיומיים / קשר / צמיחה הם של אלדרפר (ERG)** — שלוש רמות המקבצות את חמש הרמות של מסלאו, ולא שמות של קומות בפירמידה של מסלאו עצמו.
- **תיאוריות התהליך הן שלוש** (לוק, אדמס, ורום). פורטר-ולולר אינו נכלל.
- **ניסויי הארלו** בסיכום החדש הם ניסויי ההיקשרות בקופי רזוס («אם המגבת ואם התיל»), ולא ניסוי המנגנון המכני.

> נקודה אחת נותרה סותרת בתוך הסיכום עצמו: גוף הסיכום אומר שממדי אוהיו **אינם תלויים** זה בזה, ואילו מפתח התשובות שבסופו מנוסח «תלויים זה בזה». נכתב לפי גוף הסיכום, וההסתייגות מופיעה בחוברת.

## תכונות

- **מצב תרגול** — משוב והסבר אחרי כל שאלה, ותרגול חוזר של השגויות. אורך סבב נבחר (20 / 40 / הכל).
- **סימולציית מבחן** — 25 / 40 / הכל, שעון אופציונלי, מפת שאלות, ציון וסקירה מלאה של כל שגיאה.
- **הדפסת שאלות** — עם תשובות והסברים, או השאלות בלבד (שתי עמודות, צפוף).
- **פריסה מאוזנת בין נושאים** (ברירת מחדל) — הנושאים אינם שווים בגודלם, ודגימה אקראית הייתה מרכזת סבב קצר בשניים-שלושה נושאים.
- **ערבוב תשובות בכל סבב** · סינון לפי נושא ולפי מקור · מצב כהה/בהיר · מותאם למובייל.

## בנייה מחדש

```bash
cd src && python build.py
```

```bash
cd exam && python build.py
```

`src/build.py` משבץ את `bank*.js` בתוך `src/template.html` וכותב את `index.html` ואת העותק בתיקיית הקורס. `exam/build.py` עושה את אותו הדבר לחוברת, מ-`exam/content.js`.

לגרסת הוורד — `exam/to_docx.py`, שקורא את אותו `content.js` (דרך `content.json`) ובונה ממנו מסמך דו-טורי. כלומר החוברת וקובץ הוורד לעולם אינם מתפצלים: שניהם נגזרים מאותו מקור.

סכמת שאלה:

```js
{t:"נושא", s:"מקור", q:"השאלה", o:["א","ב","ג","ד"], c:1, e:"הסבר"}
```

`c` הוא אינדקס התשובה הנכונה **לפני** הערבוב. מכיוון שהאפליקציה מערבבת את סדר האפשרויות בכל הרצה, **אין לכתוב מסיחים תלויי-מיקום** ("כל התשובות נכונות") — הבנייה נכשלת עליהם.

### הבדיקות שרצות בכל בנייה

- **מבנה** — 4 אפשרויות שונות, שדות מלאים, אין כפילויות, אין מסיחים תלויי-מיקום, אין ביטויים חוזרים, הסבר באורך סביר.
- **התאמת מפתח** — התראה כשההסבר מתאר אפשרות אחרת מזו שסומנה כנכונה.
- **תל האורך** — הבדיקה החשובה. כשכותבים שאלות בכמות, התשובה הנכונה יוצאת כמעט תמיד הארוכה ביותר, ואז אפשר לענות נכון בלי לקרוא. מקרי ≈ 25%; חריגה מעל 45% נכשלת.

  נכון לעכשיו: **ארוכה 26% · קצרה 9% · "החורגת ביותר" 18%** — אף אסטרטגיה עיוורת אינה עדיפה על ניחוש.
- **בחוברת** — בקרת גלישה: עמוד שתוכנו חורג מגבולות A4 מסומן באדום בדפדפן, והסטטוס בראש העמוד מדווח «10 עמודים · תקין». הבנייה גם מזהירה אם מספר עמודים המוצהר ב-README התיישן.

> **מגבלת 5 הדפים היא רצפה של מקטעים, לא רק של תוכן.** כל מקטע פותח עמוד, ולכן 12 מקטעים = 12 עמודים גם כשהתוכן דליל. אחרי שהחוברת הורחבה ידנית ל-58 אלף תווים (כמעט כפול), ההתכנסות ל-10 עמודים הגיעה מארבעה שינויים: מיזוג המקטעים לשישה · גופן 8.9px · שער שהפך לרצועה בראש עמוד 1 במקום עמוד שלם · והשינוי המשמעותי ביותר — **מקטע חדש ממשיך בעמוד קיים כשנשאר בו יותר מ-40% מקום**. בלעדיו שלושה עמודים נותרו מלאים ב-14%-37%.

### מסלול העדכון של החוברת

החוברת נערכת **בוורד**, לא ב-`content.js`:

```bash
cd exam && python from_docx.py "<נתיב לקובץ הוורד>" && python build.py && python to_docx.py
```

`from_docx.py` מפרק את הוורד בחזרה למבנה (מקטע / כותרת / פריט / טבלה / **תמונה**) לפי הגופנים ש-`to_docx.py` כתב, ומשחזר גם הדגשות. תמונות מכווצות לרוחב טור (680px), נשמרות PNG ועוברות ל-JPEG רק כשזה מקטין, ומוטמעות כ-data-URI כדי שהחוברת תישאר קובץ יחיד. `content.js` נכתב מחדש בכל ייבוא — ולכן אין לערוך אותו ידנית. תיקוני הקלדה חד-פעמיים יושבים ב-`FIXUPS` שבתוך `from_docx.py`, כדי שישרדו ייבוא חוזר.
